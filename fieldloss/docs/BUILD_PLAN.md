# FieldLoss approved build plan

Build the user-approved 12-hour local demo: Next.js 16, React, TypeScript, Tailwind 4, Public Sans, Lucide, Zod, OpenAI transcription and strict structured extraction. Three crops (tomatoes, bananas, taro), three post-harvest stages (handling, storage, transport), Australia and Fiji. Local-only localhost hosting and versioned browser persistence.

Flat palette: #F4F7F7, #FFFFFF, #142B33, #006D77, #8A5A00, #B33C2E. Four-pixel corners, thin borders, no shadows/gradients. Accessible labelled controls and a mobile layout. Desktop review puts transcript beside editable fields.

Capture -> clarify -> review -> confirm -> act. Preserve evidence, do not invent quantities, allow unknown cause, resolve context conflicts explicitly. Normalize grams/kg/tonnes; crates require an officer-provided conversion. Count discarded/composted quantities, exclude donation/resale/feed/productive use. Support split destinations. Never confirm incomplete or impossible quantities. Loss % is lost mass divided by mass entering this stage; this is not an official FLI.

New observation, Records, Benchmark. Six labelled samples; CSV export and filters. Prevent duplicate confirmation, preserve drafts on reload and errors, offer manual entry. Benchmark five paired scenarios using shared validation, identical presets and confirmation-inclusive timers. Exclude benchmark trials from operational records. Report median times and fully correct records; never invent measured outcomes.

Verify unit calculations, validation, missing values, conflicts, mic/API failures, persistence, CSV, keyboard access, and 375/768/1440 layouts. Run tests, typecheck, production build and local production smoke check. Live AI rehearsal depends on a locally configured API key.

Deferred: photos, cloud sync, auth, FAO submission, national FLI, emissions-savings claims.
